# gemini-check

Проверяет, отвечает ли обычный **веб-чат Gemini через сервер или прокси**, без API-ключа. Браузерный режим открывает сайт в Chromium, отправляет короткое сообщение с уникальной меткой и проверяет новый ответ модели. Без внешнего прокси запросы принудительно идут через IPv4 сервера.

Это помогает владельцу VPN проверить конкретный выход: европейская страна в геобазе и открывшаяся стартовая страница ещё не подтверждают работу чата. Успех подтверждает работу Gemini Web на этом маршруте в момент проверки, но не доступ всем аккаунтам и не будущую репутацию IP.

Браузерный режим по умолчанию выводит только IP, результат и причину с кодом, если он найден. Успешная проверка занимает две строки:

~~~text
IP: 203.0.113.10 (DE)
Gemini: РАБОТАЕТ
~~~

Для прежнего подробного отчёта добавьте `--verbose`. Флаги `--browser-dialog-info` и `--browser-page-info` отдельно включают соответствующую диагностику, а `--json` сохраняет все структурированные поля.

## Запуск одной командой на VPS

На Debian 12/13 или Ubuntu 22.04/24.04/26.04 выполните от root:

~~~bash
bash <(curl -fsSL https://raw.githubusercontent.com/4jj2gp42m7-prog/gemini-check/main/gemini-check.sh) --auto --ipv4
~~~

Для скачивания нужны Bash и curl. Дальше скрипт сам установит недостающий Python, модуль venv, сертификаты, отдельное окружение Playwright, Chromium и его системные библиотеки, затем проверит обычный веб-чат. Также подходит пользователь с sudo без запроса пароля. Графический рабочий стол не требуется.

**API-ключ не нужен и не запрашивается.** `--auto` включает браузерную проверку и не использует Gemini Developer API, даже если в окружении задан `GEMINI_KEY`.

`--ipv4` явно указывает нужный выход. Прямой браузерный режим использует IPv4 и без этого параметра. IPv6 на сервере не отключается, сетевые настройки других программ не меняются.

Для выхода через прокси:

~~~bash
bash <(curl -fsSL https://raw.githubusercontent.com/4jj2gp42m7-prog/gemini-check/main/gemini-check.sh) --auto --proxy 'socks5h://127.0.0.1:40000'
~~~

В этом случае семейство выхода выбирает внешний прокси. Сочетание `--proxy` с явным `--ipv4` отклоняется: скрипт не выдаёт неизвестный выход прокси за подтверждённый IPv4.

При повторном запуске скрипт проверит, что готовый Chromium запускается, и переиспользует окружение без повторной установки пакетов и скачивания браузера. Разовый запуск не создаёт команду в `/usr/local/bin`.

Если старое браузерное окружение использует несовместимый Python, оно сохраняется рядом в папке `browser-venv.previous-*`, а новое создаётся отдельно. Профили Google при этом не затрагиваются.

Автоматическая установка системных пакетов выполняется только в явном режиме `--auto`. Скрипт не делает `apt upgrade`, не меняет DNS и маршруты и не перенастраивает службы. Установочные сообщения идут в stderr; после подготовки с `--auto --json` в stdout остаётся диагностический JSON.

На macOS `--auto` может использовать уже подготовленное окружение или доступный Python 3.10+. Сам Python через Homebrew скрипт не устанавливает. Подготовка Linux с нуля ограничена указанными версиями Debian и Ubuntu.

## Установка постоянной команды и ручной контроль

Если окружение уже установлено и на VPS работает VPN-нода, для повторной проверки используйте `--browser --ipv4` вместо `--auto`. Этот режим не устанавливает пакеты, не перезапускает ноду и не меняет фаервол, DNS или системный IPv6. Chromium расходует память, CPU и сеть; при недостатке ресурсов он может повлиять на работу других процессов.

Чтобы установить или обновить команду `gemini-check`, выполните с правами записи в `/usr/local/bin`:

~~~bash
curl -fsSL https://raw.githubusercontent.com/4jj2gp42m7-prog/gemini-check/main/gemini-check.sh -o /usr/local/bin/gemini-check && chmod +x /usr/local/bin/gemini-check
~~~

После этого установка всего необходимого и проверка тоже выполняются одной командой:

~~~bash
gemini-check --auto --ipv4
~~~

Если нужно управлять установкой отдельно, остаются ручные режимы:

~~~bash
gemini-check --install-browser
gemini-check --browser --ipv4
~~~

Они требуют Python 3.10+ и не устанавливают системные пакеты автоматически. `--install-browser` создаёт отдельное Python-окружение, устанавливает **Playwright 1.64.1** и скачивает Chromium. Системные Python-пакеты не меняются. По умолчанию окружение находится здесь:

~~~text
~/.local/share/gemini-check/browser-venv
~~~

Если задан `XDG_DATA_HOME`, используется его папка `gemini-check`. Переменная `GEMINI_BROWSER_HOME` задаёт другую папку данных. Скрипт сам выбирает установленный runtime. Кеш Chromium остаётся в штатной папке Playwright; установку и проверки запускайте от одного пользователя.

Если версия обычного `python3` ниже 3.10, установщик ищет подходящий Python. Можно указать его явно:

~~~bash
GEMINI_BROWSER_PYTHON=/usr/bin/python3.12 gemini-check --install-browser
~~~

На Debian/Ubuntu для создания окружения может понадобиться пакет:

~~~bash
apt install python3-venv
~~~

Ручной режим `--install-browser` не запускает apt или sudo. Если Chromium сообщит о недостающих системных библиотеках, используйте `--auto` или выполните отдельно с нужными правами:

~~~bash
"${GEMINI_BROWSER_HOME:-${XDG_DATA_HOME:-$HOME/.local/share}/gemini-check}/browser-venv/bin/python" -m playwright install-deps chromium
~~~

Текущие поддерживаемые платформы Playwright: Debian 12/13, Ubuntu 22.04/24.04/26.04 и macOS 14+. На Linux поддерживаются x86-64 и arm64.

## Что именно проверяет браузер

1. Создаётся чистый временный профиль, если отдельный профиль не указан.
2. Для прямого режима запускается временный локальный CONNECT-прокси, который устанавливает соединения только по IPv4. Он доступен на `127.0.0.1` и закрывается после проверки.
3. Cloudflare trace открывается в том же браузерном сеансе для определения внешнего IP, страны, узла и WARP.
4. Открывается сайт Gemini и отправляется тестовое сообщение через тот же IPv4-маршрут. При заданном внешнем прокси используется его маршрут.
5. Проверяется новый видимый ответ модели с уникальной меткой и наблюдаемая отправка запроса генерации.

Локальный канал не меняет DNS, маршруты или `sysctl` и не отключает IPv6 в системе. Его исходящие соединения создаются только с семейством `AF_INET`; браузер не переключается незаметно на прямой IPv6-выход.

HTTP 200, поле ввода, старый ответ и текст собственного сообщения успехом не считаются. Если интерфейс Google изменится и ответ нельзя надёжно распознать, результат останется неопределённым.

Лимит браузерной проверки по умолчанию 60 секунд, допустимо от 15 до 300:

~~~bash
gemini-check --browser --browser-timeout 120
~~~

Ввод и ожидание доступности кнопки используют оставшееся время общего лимита. Перед отправкой Chromium/Playwright проверяет возможность клика без самого клика. Если перекрыта только кнопка, скрипт может отправить сообщение одним нажатием Enter из уже сфокусированного редактора. Для этого редактор должен оставаться доступным, содержать тестовое сообщение; диалоги, меню и подсказки должны быть закрыты. Если слой перекрывает и редактор, скрипт ждёт. В отчёте указан способ отправки или причина, по которой Enter недоступен.

Проверки доступности могут повторяться, реальная отправка выполняется один раз. После ошибки действия скрипт продолжает искать свежий ответ в пределах оставшегося времени.

Мешающие окна Gemini обрабатываются автоматически: скрипт закрывает их кнопкой Close/«Закрыть»/Dismiss, а в окнах условий, конфиденциальности и первого запуска может нажать I agree/Accept/Continue/Got it и соответствующие русские кнопки. В распознанном окне cookies предпочтителен Reject all; если его нет, допускается Accept all. Обрабатывается не более трёх действий с окнами за проверку; одинаковое действие в неизменившемся окне не повторяется. Вход в аккаунт и оформление оплаты автоматически не выполняются.

Если окно не распознано или не закрывается, результат сразу сообщает о диалоге. Чтобы увидеть его заголовок и кнопки в чистом временном браузере, добавьте `--browser-dialog-info`. Флаг не совмещается с `--browser-profile`; содержимое чатов, HTML и cookies не выводятся. Обычный режим сохраняет только тип окна и результат действия.

При незавершённой проверке выводятся этап, время и наличие запроса генерации к Google. При исключении добавляется безопасный код причины: например, `blocked_by_overlay` означает перекрытую кнопку, `element_detached` означает исчезнувший элемент, `page_closed` означает закрывшуюся страницу или браузер. Эти признаки помогают найти сбой проверки; они не устанавливают причину решения Google по IP или нехватку памяти на сервере.

Новое уведомление сайта «Something went wrong» после отправки выводится как ошибка сайта, без вывода о блокировке IP. HTTP 200 означает получение заголовков запроса; он не доказывает получение ответа модели. Счётчики `browser.backend_requests` показывают наблюдаемые запросы веб-сервиса: `total`, `finished`, `failed`, `pending`. Среди них бывают служебные запросы и открытые потоки даже при успешном чате, поэтому эти числа не определяют успех проверки.

Скрипт наблюдает POST и поток GET `processSession`, включая получаемые части незавершённого потока через Chromium CDP. Данные запросов не меняются. Распознаются явные JSON-объекты ошибки Google, JSON-ошибки в рамках WebChannel и статусы gRPC-Web. Произвольные числовые массивы не считаются ошибками: служебный ответ `[0,0,7]` не означает `PERMISSION_DENIED`. Чтение полного тела выполняется только после `requestfinished`; активные потоки не ожидаются через `response.body()`.

В `browser.response_error` записываются источник, код, статус и расшифровка. В JSON Google поле `error.code` обычно является HTTP-кодом, а `error.status` содержит канонический статус. Для gRPC код 7 означает отказ в доступе, 8 — лимит, 16 — требование входа, 4 — превышение времени ответа, 13/14 — ошибку сервиса. Код 9 сам по себе не доказывает региональное ограничение: для такого вывода требуется явное сообщение о неподдерживаемом регионе. Код из уведомления самого Gemini помечается как `gemini_ui` и не подменяется расшифровкой gRPC.

Подтверждённый новый ответ с контрольной меткой имеет приоритет над ошибкой фонового запроса. Если ответ не получен и известная ошибка не найдена, вывод прямо сообщает «Код ошибки не найден»; успешность по HTTP 200 не объявляется. Неизвестные внутренние форматы Google не расшифровываются догадками.

Если получен `400 FAILED_PRECONDITION`, добавьте `--browser-error-info`: в ту же короткую строку ошибки попадёт пояснение `message` Google и, если доступен, машинный `ErrorInfo.reason`. Этот код означает невыполненное условие запроса; без явной причины он не считается региональным баном. Известные причины неподдерживаемой страны, требования входа или недействительной сессии уточняют результат. Режим доступен только для чистого профиля. Адреса почты, URL, токены, cookies и длинные идентификаторы редактируются; `metadata`, `DebugInfo` и идентификаторы ресурсов из `details` не выводятся.

Если сообщение отправлено, но ответ не подтверждён, добавьте `--browser-page-info`: в отчёте появятся последние строки видимого текста сайта, наличие тестового сообщения пользователя и число известных контейнеров ответа. Это диагностика, а не дополнительный способ признать чат рабочим. Флаг доступен только для чистого временного браузера, без `--browser-profile`; HTML, cookies, тела сетевых ответов не сохраняются. Без флага видимый текст страницы в отчёт не попадает.

| Результат | Что означает |
|---|---|
| Чат работает | Получен новый ответ на тестовое сообщение через сайт Gemini |
| Региональный отказ | Сайт явно сообщил об ограничении региона |
| Отказ в доступе | Браузерный запрос запрещён; точная причина решения Google не установлена |
| Нужен вход в Google | Анонимную проверку завершить нельзя; это не блокировка IP |
| CAPTCHA / проверка браузера | Требуется дополнительная проверка; это не доказательство регионального бана |
| Нужно согласие | Работа чата не подтверждена, пока страница согласия не пройдена |
| Диалоговое окно мешает чату | Окно не удалось обработать автоматически; заголовок и кнопки доступны с `--browser-dialog-info` |
| Семейство выхода не подтверждено | Например, Cloudflare видит IPv6 при принудительном IPv4-транспорте. Возможна внешняя трансляция или другой маршрут; это не бан |
| Ошибка сети / таймаут / неизвестный интерфейс | Работа не подтверждена; результат не следует считать баном |
| Страница / браузер закрылись | Проверка прервана; причина закрытия не установлена |
| Страница Chromium упала | Браузер сообщил о падении страницы; причина падения не установлена |
| Не установлены зависимости | Нужно установить Playwright/Chromium или системные библиотеки |

Текстовые запросы без Google-входа доступны не всем: это зависит от региона и устройства. Кнопка Sign in на странице сама по себе не означает обязательный вход.

## Если нужен Google-аккаунт

На компьютере с графическим экраном можно открыть видимый Chromium и вручную войти в Google:

~~~bash
gemini-check --browser --headed --browser-profile ~/gemini-check-profile --browser-timeout 180
~~~

Выполните вход в открывшемся окне. Скрипт не спрашивает пароль Google. Затем можно использовать тот же профиль без окна:

~~~bash
gemini-check --browser --browser-profile ~/gemini-check-profile
~~~

Папка должна быть новой, пустой или ранее созданной gemini-check. Личный профиль Chrome указывать нельзя. Отдельный профиль хранит локальные cookies и данные входа; не публикуйте и не пересылайте его. В диагностический JSON они не записываются.

`--headed` требует графического экрана. На VPS без рабочего стола используйте стандартный режим; запрос входа или CAPTCHA будет отображён отдельно, без вывода о блокировке IP.

## Проверка выхода VPN или прокси

Браузер на VPS проверяет **маршрут Chromium с этого VPS**. Если VPN направляет Google через отдельный SOCKS/WARP или другой outbound, проверяйте именно этот выход:

~~~bash
gemini-check --browser --proxy 'socks5h://127.0.0.1:40000'
~~~

Сохраняются позиционный формат и переменная окружения:

~~~bash
gemini-check --browser 'socks5h://127.0.0.1:40000'
GEMINI_PROXY='http://127.0.0.1:3128' gemini-check --browser
~~~

Поддерживаются HTTP(S)-прокси, в том числе с авторизацией, и SOCKS5 без авторизации. `socks5h://` преобразуется в `socks5://`: Chromium разрешает имена через SOCKS-прокси. **SOCKS5 с логином и паролем Chromium не поддерживает**. Скрипт вернёт `proxy_unsupported` и не переключится незаметно на прямое соединение. Для такого прокси нужен совместимый локальный relay.

Переменные `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` и системный прокси не определяют проверяемый выход. Укажите его явно или через `GEMINI_PROXY`. Если пароль написан прямо в команде запуска, он может остаться в истории оболочки или аргументах команды.

Без внешнего прокси `--browser` и `--auto` принудительно используют IPv4. Разрешены `--ipv4` и короткая форма `-4`. Параметры `--ipv6` и `--both` для браузера не поддерживаются; они остаются доступны в диагностике curl.

При заданном `--proxy` браузер использует внешний прокси, который сам выбирает семейство назначения. Поэтому `--proxy` нельзя сочетать с явным `--ipv4` или `-4`. Это также относится к прокси из `GEMINI_PROXY` и позиционного аргумента.

Результат браузера имеет отдельный маршрут `browser`. Внешний IP по Cloudflare относится к этому браузеру, но при раздельной маршрутизации по доменам Google может использовать другой выход. Если Cloudflare возвращает IPv6 при принудительном IPv4-транспорте, итог остаётся неопределённым, а не положительным или региональным отказом.

### Как связать отказ с выходом сервера

Проверьте проблемный выход A, затем заведомо рабочий B и снова A. Сохраняйте тот же браузерный профиль, аккаунт и настройки.

Если отказ воспроизводится на A, а через B приходит ответ, это сильный признак зависимости от сети или выхода. Он не раскрывает внутреннюю причину решения Google и не доказывает наличие общего blacklist IP. Успех анонимного чата не обещает доступ к платным функциям или любому аккаунту.

## Сравнение во времени и JSON

Сохраните результат, пока Gemini работает:

~~~bash
gemini-check --browser --save before.json
~~~

При появлении проблемы сравните новый запуск:

~~~bash
gemini-check --browser --compare before.json --save after.json
~~~

Сравнение показывает изменение внешнего IP и статусов. Для проверки одного маршрута сохраняйте одинаковые настройки и, если нужен аккаунт, тот же отдельный профиль. Смена IP означает сравнение разных выходов.

Машиночитаемый вывод:

~~~bash
gemini-check --browser --json --save report.json
~~~

JSON содержит время, IP и результаты. API-ключи, cookies, пароль прокси, полные тела ответов и содержимое профиля в него не записываются. Файл сохраняется с правами `600`.

В `browser.stage` указан этап проверки, в `elapsed_ms` её длительность, в `diagnostics` безопасные признаки найденного редактора и выполненных действий. В `submit_method` записывается `click` или `enter`, в `keyboard_fallback_blocked` причина недоступности Enter. Поля `dialog_kind`, `dialog_action`, `dialog_action_attempts` и `dialogs_closed` описывают обработку окон. Только при явном `--browser-dialog-info` поле `browser.dialogs` содержит заголовки и подписи кнопок. Поле `error`, если оно есть, содержит только контролируемые `kind`, `reason` и имя класса исключения `type`; такой же безопасный объект может быть в `diagnostics.submit_action_error`, если действие завершилось ошибкой, но проверка ответа продолжилась. Исходный текст исключения и журнал Playwright в отчёт не попадают.

Фоновые запросы `processSession` тоже могут получать HTTP 200, поэтому такой ответ сам по себе не подтверждает отправку нашего сообщения или работу чата. Запросы учитываются после начала реального действия; успешный результат требует нового ответа модели с контрольным маркером. При ошибке действия факт отправки сохраняется, если замечен запрос с самим маркером или получен проверенный ответ. Повторной отправки нет.

В `browser.transport` указывается маршрут: `family: "ipv4"` для локального IPv4-канала или `"proxy"` для внешнего прокси. Поле `connections` содержит узлы и адреса установленных соединений, а `failures` помогает разобраться в ошибках транспорта. Адреса узлов сайта в этом списке не являются публичным IP пользователя; внешний адрес показывается отдельно по Cloudflare.

## Дополнительная диагностика curl и API

Без `--browser` и `--auto` остаётся прежний режим с отдельными проверками IPv4 и IPv6 через curl. Ему достаточно **Python 3.8+**, Playwright не нужен:

~~~bash
gemini-check --ipv4 --no-api
gemini-check --ipv6 --no-api
gemini-check --no-api
~~~

Он показывает ipinfo, Cloudflare, страну YouTube и признаки из HTML Gemini. Это предварительная диагностика; она не отправляет сообщение через веб-чат.

При обычном запуске без `--no-api` и без прокси предлагается скрытый ввод ключа Gemini API. Для прокси используйте `GEMINI_KEY` или `--key-file`. Сохраняется `GEMINI_KEY=-` для пропуска API:

~~~bash
gemini-check --ipv4 --key-file /путь/к/gemini.key
gemini-check --ipv4 --model gemini-flash-lite-latest
~~~

С ключом выполняется небольшая генерация через Developer API: обычно одна на маршрут, максимум две при недоступной модели или перегрузке. На платном проекте запрос может расходовать оплачиваемые токены. Ошибки ключа, прав проекта, billing и квоты отличаются от регионального отказа. Список моделей, HTTP 429 и HTTP 503 не считаются успехом.

Успех API подтверждает API, а не пользовательский веб-чат. YouTube и обычные геобазы тоже не заменяют браузерный тест.

## Параметры

| Параметр | Действие |
|---|---|
| `--auto` | Установить недостающие зависимости и проверить Gemini Web без API-ключа; прямой выход по IPv4 |
| `--browser` | Реальный тест обычного Gemini Web с уже установленным Chromium; прямой выход по IPv4 |
| `--install-browser` | Отдельно установить Playwright и Chromium |
| `--browser-timeout SEC` | Лимит браузерной проверки: 15..300 секунд, по умолчанию 60 |
| `--headed` | Показать окно; нужен `--browser` или `--auto` и графический экран |
| `--browser-profile DIR` | Отдельный профиль для ручного Google-входа |
| `--browser-dialog-info` | Заголовок и кнопки мешающего окна; только чистый профиль |
| `--browser-page-info` | Видимый текст сайта и признаки сообщения/ответа; только чистый профиль |
| `--browser-error-info` | Короткое сообщение Google и машинный код причины; только чистый профиль |
| `--verbose` | Полный браузерный отчёт вместо краткого результата |
| `--proxy URL` или позиционный URL | Проверить прокси; также доступна `GEMINI_PROXY` |
| `--json` / `--save FILE` / `--compare FILE` | Вывод, сохранение и сравнение отчётов |
| `--ipv4`, `-4` | IPv4 для прямого браузерного режима или диагностики curl; с внешним прокси в браузере не совмещается |
| `--ipv6`, `-6` / `--both` | Семейство только для curl; без выбора curl проверяет оба |
| `--no-api` | Пропустить API в режиме curl |
| `--key-file FILE` | API-ключ из локального файла, только для режима curl/API |
| `--model MODEL` | Модель Developer API вместо автоматического выбора |
| `--timeout SEC` | Лимит curl-запроса: 5..60 секунд, по умолчанию 12 |
| `--help` / `--version` | Справка или версия |

`--auto` допускает `--ipv4` для прямого выхода, прокси без `--ipv4`, а также `--json`, `--save`, `--compare`, `--headed`, `--browser-profile` и `--browser-timeout`. Параметры `--ipv6`, `--both`, `--key-file`, `--model` и `--install-browser` с ним не совмещаются.

`--install-browser` запускается отдельно от проверок. Параметры `--key-file` и `--model` с `--browser` отклоняются. Ошибка подготовки окружения в `--auto` завершается кодом `2`; проверка Gemini в этом случае не запускается.

## Коды завершения

| Код | Браузерный режим | Дополнительный режим curl/API |
|---|---|---|
| `0` | Новый ответ модели подтверждён | API подтверждён на проверяемых рабочих маршрутах |
| `1` | Явный региональный отказ или отказ в доступе | Явный отказ, HTTP 403/CAPTCHA либо смешанный результат Web и API |
| `2` | Вход, CAPTCHA, согласие, таймаут, ошибка сети, несовпадение семейства IP или недостаточно данных | Без ключа, ошибки ключа/квоты/billing/сети или неопределённость |
| `64` | Неверные аргументы | Неверные аргументы |

В дополнительном двойном режиме отсутствие IPv6 само по себе не считается баном. Если при запросе IPv6 внешние сервисы видят IPv4, семейство выхода не подтверждено. CAPTCHA и HTTP 403 сами по себе не доказывают региональный бан ни в одном режиме.
