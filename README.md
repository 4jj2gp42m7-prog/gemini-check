# gemini-check

Диагностика сервера или прокси для Gemini. Помогает владельцу VPN понять, откуда идёт запрос, есть ли явный отказ Google по региону и отвечает ли модель через Gemini API. IPv4 и IPv6 проверяются отдельно.

Европейская страна в геобазе не гарантирует работу Gemini. Google может определять регион иначе; ошибки ключа, аккаунта, квоты и самого сервиса тоже влияют на доступ. Скрипт показывает факты проверки и не объявляет сервер подходящим только по стране YouTube или ответу HTTP 200 от сайта.

## Быстрый запуск

Нужны **Bash, curl и Python 3.8 или новее**. Сторонние Python-пакеты и `pip` не используются. Скрипт не меняет DNS, маршруты или настройки сервера.

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/4jj2gp42m7-prog/gemini-check/main/gemini-check.sh)
```

При обычном запуске из терминала без прокси скрипт предложит ввести **ключ Gemini API**. Ввод скрыт; Enter пропускает API-проверку. Ключ можно получить в [Google AI Studio](https://aistudio.google.com/apikey). Ключ передаётся только Google. Для проверки прокси задайте ключ через `GEMINI_KEY` или `--key-file`, иначе API будет пропущен.

С ключом скрипт делает небольшой тестовый запрос к модели. На платном проекте он может расходовать оплачиваемые токены. Обычно выполняется одна генерация на маршрут; при недоступности модели или перегрузке возможна вторая. При ошибке ключа или квоты дополнительные модели не перебираются.

Проверить только предварительные признаки без ключа и без вопросов:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/4jj2gp42m7-prog/gemini-check/main/gemini-check.sh) --no-api
```

## Установка и обновление

```bash
curl -fsSL https://raw.githubusercontent.com/4jj2gp42m7-prog/gemini-check/main/gemini-check.sh -o /usr/local/bin/gemini-check && chmod +x /usr/local/bin/gemini-check
```

Та же команда обновляет установленную версию. Для записи в `/usr/local/bin` нужны соответствующие права.

После установки:

```bash
gemini-check
gemini-check --ipv4
gemini-check --ipv6 --no-api
```

## Что означают результаты

Скрипт разделяет **Gemini Web** и **Gemini API**: у них разные условия доступа и списки стран.

| Проверка | Что она подтверждает |
|---|---|
| Gemini Web: сайт доступен | Страница открылась по проверяемому маршруту. Это ещё не подтверждение работы чата после входа |
| Gemini Web: явное ограничение региона | Страница или редирект непосредственно сообщает о региональном отказе |
| Gemini API: модель ответила | Тестовая генерация прошла с этим ключом, моделью и маршрутом в момент проверки |
| Gemini API: отказ по региону | Сам API явно сообщил, что местоположение не поддерживается |
| Ошибка ключа / проекта / оплаты | Нужно проверить ключ, его ограничения, проект или billing; это не доказательство блокировки IP |
| Квота, HTTP 429 | Лимит запросов или токенов. Успешная генерация не подтверждена |
| Перегрузка, HTTP 503 | Временный отказ сервиса. Успешная генерация не подтверждена |
| Сетевая ошибка | Проблема DNS, TLS, соединения, таймаут или недоступный прокси; причина отображается отдельно |
| Нет IPv6 | У сервера может отсутствовать рабочий IPv6. Само по себе это не ограничение Google |
| Семейство выходного IP не совпало | Например, при проверке IPv6 внешние сервисы увидели IPv4. Оценка маршрута остаётся неподтверждённой; нужно проверить трансляцию или перехват соединения |

Успешная генерация через API подтверждает **доступ API**, но не обещает работу сайта или мобильного приложения под любым аккаунтом. Без ключа результат остаётся предварительным: открывшаяся анонимная страница не заменяет проверку реального сообщения в чате.

Дополнительные признаки нужны для сопоставления:

| Данные | Как использовать |
|---|---|
| Cloudflare trace: IP, страна, `colo`, WARP | Сравнить внешний IP и страну с другими проверками. `colo` означает узел Cloudflare, а не местоположение пользователя |
| ipinfo: страна, провайдер | Справочная геобаза; она не определяет решение Google |
| Страна YouTube | Дополнительный сигнал того, как один из сервисов Google видит запрос. Она не гарантирует ту же оценку в Gemini |
| Страна из страницы Gemini, если извлечена | Эвристика по внутренним данным HTML. Формат Google может измениться; отсутствие поля не означает блокировку |

Если IP или страны расходятся, проверьте маршруты и прокси. При раздельной маршрутизации Google и сервисы определения IP могут выходить через разные адреса.

## Проверка прокси и маршрутов VPN

Без прокси по умолчанию отдельно проверяются IPv4 и IPv6. Выбрать семейство можно через `--ipv4` / `-4`, `--ipv6` / `-6` или `--both`. Переменные `HTTP_PROXY`, `HTTPS_PROXY` и `ALL_PROXY` не используются: для проверки прокси задайте его явно или через `GEMINI_PROXY`.

Прокси можно передать как раньше позиционным аргументом:

```bash
gemini-check 'socks5h://логин:пароль@хост:порт'
```

Или через параметр / переменную окружения:

```bash
gemini-check --proxy 'socks5h://127.0.0.1:40000'
GEMINI_PROXY='socks5h://127.0.0.1:40000' gemini-check --no-api
```

Для SOCKS-прокси `socks5h://` передаёт разрешение имён прокси. Через прокси проверяется один маршрут. Сочетать его с `-4`, `-6` или `--both` нельзя: семейство соединения до прокси не гарантирует семейство его выхода к Google.

Запуск непосредственно на VPS проверяет соединение **curl с этого VPS**. Если VPN отправляет Google через отдельный SOCKS/WARP или другой outbound, проверяйте именно этот выход через прокси. Маршрутизация клиентского VPN может отличаться от обычного подключения сервера.

## Сравнение во времени

Чтобы заметить ухудшение после периода нормальной работы, сохраните отчёт успешной проверки:

```bash
gemini-check --ipv4 --save before.json
```

Когда появится проблема, сравните с ним новый запуск:

```bash
gemini-check --ipv4 --compare before.json --save after.json
```

Сравнение помогает увидеть изменение IP, стран, доступности сайта, результата API, выбранной модели и её версии. Для проверки изменения именно сети используйте тот же ключ, модель и маршрут. Разница результатов сама по себе не доказывает причину: на неё также могут повлиять состояние проекта и временный сбой Google.

Отчёт JSON содержит время и результаты диагностики. Ключи, cookies, пароль прокси и полные тела ответов в него не записываются. IP и сведения о сети в отчёте остаются. Файл сохраняется с правами `600`.

Машиночитаемый вывод без интерактивного запроса ключа:

```bash
gemini-check --json --no-api
gemini-check --ipv4 --key-file /путь/к/gemini.key --json --save report.json
```

Второй пример требует заранее созданного файла с вашим ключом. Файл ключа тоже следует хранить с доступом только владельцу. Сохраняется совместимость с переменными `GEMINI_KEY` и `GEMINI_KEY=-` для пропуска API.

## Параметры

| Параметр | Действие |
|---|---|
| `--ipv4`, `-4` | Только прямое IPv4-соединение |
| `--ipv6`, `-6` | Только прямое IPv6-соединение |
| `--both` | Раздельно IPv4 и IPv6, режим по умолчанию без прокси |
| `--proxy URL` или позиционный URL | Проверить указанный прокси; также доступна `GEMINI_PROXY` |
| `--no-api` | Пропустить API и запрос ключа |
| `--key-file FILE` | Прочитать ключ из файла |
| `--model MODEL` | Проверять указанную модель без предварительного получения списка моделей |
| `--timeout SEC` | Таймаут одного HTTP-запроса: от 5 до 60 секунд, по умолчанию 12 |
| `--json` | Вывести JSON; не спрашивать ключ интерактивно |
| `--save FILE` | Сохранить отчёт JSON |
| `--compare FILE` | Сравнить результат с предыдущим отчётом |
| `--help` | Показать справку |
| `--version` | Показать версию скрипта |

Например, проверить конкретную модель:

```bash
gemini-check --ipv4 --model gemini-flash-lite-latest
```

Без `--model` скрипт выбирает подходящую лёгкую модель из ответа Google. Сам доступ к списку моделей не считается успешной проверкой Gemini. Таймаут относится к отдельному запросу, а не всему запуску.

Ключ и авторизация прокси не передаются в аргументах запускаемых скриптом процессов curl. Если написать пароль прямо в вашей команде запуска, он всё равно может остаться в истории оболочки или аргументах самой команды.

## Коды завершения

| Код | Значение |
|---|---|
| `0` | Доступ API подтверждён для проверяемых рабочих маршрутов; отсутствие IPv6 в стандартной двойной проверке не считается отказом |
| `1` | Найден явный отказ по региону, ограничение Web-запроса (CAPTCHA / HTTP 403) или смешанный результат Web и API. CAPTCHA и HTTP 403 сами по себе не доказывают региональный бан |
| `2` | Вывод не подтверждён: без ключа, ошибка сети, ключа, квоты, billing или временный сбой |
| `64` | Неверные аргументы запуска |

## Границы проверки и источники

Скрипт не имеет доступа к закрытой базе репутации IP Google и не предсказывает, будет ли адрес работать через неделю. Для пользовательского чата окончательная проверка: открыть Gemini через тот же VPN под своим аккаунтом и отправить сообщение. В частности, Google учитывает сведения о местоположении из IP, аккаунта и, при разрешении, устройства.

- [Доступные регионы Gemini Web](https://support.google.com/gemini/answer/13575153?hl=en).
- [Доступные регионы AI Studio и Gemini API](https://ai.google.dev/gemini-api/docs/available-regions).
- [Диагностика API: права, billing, ограничения проектов и ключей](https://ai.google.dev/gemini-api/docs/troubleshooting).
- [Ошибки GenerateContent](https://ai.google.dev/gemini-api/docs/generate-content/api-errors?hl=en).
- [Как Gemini использует местоположение](https://support.google.com/gemini/answer/13594961?hl=en).
- [RegionRestrictionCheck: пример эвристики по HTML Gemini](https://github.com/lmc999/RegionRestrictionCheck/blob/main/check.sh#L4544). Это внутренние маркеры страницы, не официальный интерфейс Google и не гарантия работы чата.
